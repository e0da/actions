# SAMOS CI M2 Manifest Runner Verification

Date: 2026-05-28

Linear: E0D-1036

## Scope

This slice adds an opt-in `runner-manifest` input to the Markdown and OpenTofu
reusable workflows. The input accepts `puck-linux-runner-image-contract.v1` JSON
generated by `ops`.

Existing callers remain compatible:

- hosted defaults stay unchanged
- raw `runner` labels still control scheduling
- empty `runner-manifest` is inert
- existing `runner-profile` and `runner-capabilities` behavior is preserved

## Verification Behavior

When `runner-manifest` is provided, the workflow validation step:

- requires schema `puck-linux-runner-image-contract.v1`
- selects the contract entry whose `runner_identity.repo` matches the caller repo
- compares `runner_identity.runner_profile` with `runner-profile` when provided
- compares intended runner OS and architecture with GitHub's observed
  `runner.os` and `runner.arch`
- checks every requested `runner-capabilities` token against the manifest tool
  entry
- fails if a requested tool is absent or has no observed version
- for Markdown `tool-mode: runner-preinstalled`, treats `lychee` as an implied
  manifest capability

This gives failures like `tools.lychee.observed.version` or
`intended_contract_state.runner_arch`, rather than later ad hoc PATH errors.

## Non-Goals

This does not make manifest verification mandatory for hosted runners. It does
not optimize Gitleaks or OpenTofu runtime, and it does not replace raw runner
labels with profile scheduling.
